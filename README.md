# Thinking Graph · Local MVP 0.2

Agent entry point: [AGENTS.md](AGENTS.md). Current checkpoint: [HANDOFF](docs/HANDOFF.md).
Current product/architecture: [PRODUCT](docs/PRODUCT.md) / [ARCHITECTURE](docs/ARCHITECTURE.md).
Dated sections below record historical changes; the shared current-state docs take precedence.

ממשק React + TypeScript + Vite, שרת Python/FastAPI, בסיס SQLite מקומי, SQLAlchemy ו־Alembic.
אין צורך ב־Cloudflare, ב־Sites, בחשבון חיצוני או במפתח API כדי להפעיל את הגרסה הזאת.

## הפעלה במחשב הנוכחי

מתוך תיקיית הפרויקט ב־CMD:

```bat
start-local.cmd
```

ב־PowerShell: `./start-local.cmd`.
פתחי http://127.0.0.1:8000 והשאירי את חלון השרת פתוח. עצירה: Ctrl+C.
התלויות ותוצר הממשק הוכנו במחשב הנוכחי במהלך העדכון. אם הם חסרים, בצעי את ההתקנה להלן.

## התקנה במחשב חדש

נדרשים Python 3.12 ו־Node 24 (גרסאות נבדקות בפרויקט), עם npm.
הפקודות הבאות מורידות תלויות; הן אינן מפרסמות או מעלות את קוד הפרויקט.
הריצי מתוך תיקיית הפרויקט, והמשיכי רק כאשר כל פקודה הצליחה:

```bat
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
npm ci
npm run build
start-local.cmd
```

ל־macOS/Linux: `python3 -m venv .venv`, ואז `.venv/bin/python -m pip install -r requirements.txt`,
`npm ci`, `npm run build`, ולבסוף `.venv/bin/python -m backend`.

השרת יוצר את בסיס הנתונים בהפעלה הראשונה ומחיל migrations חסרים אוטומטית. הוא אינו מאפס נתונים בהפעלה חוזרת.
הנתונים נשמרים ב־`data/thinking-graph.sqlite`, ביחס לתיקיית הפרויקט, ולא בתיקייה שממנה במקרה הופעלה Python.
לנתיב אחר אפשר להגדיר `THINKING_GRAPH_DB`; נתיב יחסי נפתר ביחס לשורש הפרויקט.

## התנסות ראשונה

1. לחצי על „פתיחת מרחב ושיחה”.
2. שלחי: `יש קשר בין [[שדה]] לבין [[כוח]]`.
3. לחצי על רעיון במפה כדי לערוך, לאשר או לדחות ולראות את הודעות המקור.
4. לחצי על „קשר חדש”, בחרי לפחות שני רעיונות ותני שם לקשר.
5. צרי שיחה ומרחב נוספים ושלחי שוב `[[שדה]]`: הרעיון משותף, עם קישור למקור החדש.
6. סגרי את השרת והפעילי מחדש כדי לראות שהמידע נשאר.

## גבולות הגרסה המקומית

- זהות קבועה `local:user` מתעדת פעולות. היא אינה מערכת התחברות או מנגנון הרשאות.
- השרת מאזין רק ל־127.0.0.1; אין לפרסם גרסה זו או לחשוף אותה לרשת לפני הוספת authentication ו־authorization.
- סינון Host/Origin ובקשות JSON מפחית גישה מדפי אינטרנט זרים, אך אינו מבודד משתמשים או תוכנות אחרות באותו מחשב.
- קיים חילוץ ניסיוני דרך מודל Ollama מקומי, עם בדיקה ואישור לפני הוספה למפה. אין כאן עוזר צ׳אט גנרטיבי כללי.
- שימוש חוזר מבוסס כותרת מנורמלת זהה; הוא אינו זיהוי שקילות סמנטית. אפשר לקשר מקורות ידנית.
- קשרים תומכים ב־2–12 משתתפים; חילוץ מאושר יכול לשמור תפקידי מקור/יעד. המפה תומכת בגרירה, שינוי גודל ובחירה קבוצתית.
- עריכות סדרתיות נשמרות בהיסטוריה; עדיין אין זיהוי התנגשות עריכות למערכת רב־משתמשית.
- חזרה אוטומטית/ידנית על בקשה עם אותו commandId אינה משכפלת אותה. המזהה נשמר בממשק כל עוד הבקשה הממתינה לא הוחלפה/העמוד לא נסגר.

## מבנה

- `src/`: ממשק React, מציג את הגרף דרך API מקומי.
- `backend/schemas.py`: בקשות Pydantic עם בדיקת שדות ואורכים.
- `backend/service.py`: פעולות הגרף וחוקי המוצר; שינויים, מקור והיסטוריה נשמרים בטרנזקציה אחת.
- `backend/models.py`: טבלאות SQLAlchemy. created_by הוא provenance בלבד; רעיונות מקושרים M:N למרחבים ולהודעות.
- `backend/database.py`: חיבור SQLite והפעלת migrations.
- `migrations/versions/`: היסטוריית Alembic. שינוי חדש = migration חדש; לא עורכים migration שכבר הוחל.
- `tests/`: בדיקות HTTP מול FastAPI ו־SQLite בקובץ, ללא הדמיית D1.
- `requirements.txt` ו־`package-lock.json`: גרסאות התלויות המדויקות. `requirements.in` הוא קלט לעדכונים יזומים.

ההגדרות והקוד הפעיל של Sites/Workers/D1 הוסרו. הסרת קבצים מקומיים אינה מחיקה של הרשומה החיצונית שנוצרה קודם; מחיקתה לא אושרה כבוצעה.
אם יש לך נתונים ישנים של D1 מחוץ לפרויקט, הם אינם מיובאים אוטומטית. בבדיקה המקומית לא נמצא בסיס D1 קיים בתוך הפרויקט.
